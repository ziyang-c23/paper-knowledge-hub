# 研究阅读工作台：交付与验证

本轮实现沿用唯一 `paper.note` 与本地工作区 API。四篇材料和入口见 [样例说明](reading-workbench-examples.md)。公开范围仍为 Octo；其余三篇、综合专题、原文 PDF 和个人资料留在本地。

## 已连通的路径

- 论文导读 → 数据驱动方法步骤 → 对应章节/原文；结果按任务与协议分组，图表和表格读取同一记录。
- 目录 → 章节深链接/恢复；附录默认折叠。PDF复用实例，支持缩放、文字选择、页内查找，选区问题保存文档身份与页序。
- 共享方法节点 → 关联论文 → 问题驱动比较 → 保存专题；不可用论文明确提示。
- 章节补充、实验提取、论文比较 → 本地 Agent 上下文 → 导入 → 渲染字段差异 → 选择字段应用。模型未配置时不发网络生成请求。
- 阅读问题、AI任务/上下文和待审草稿进入校验和备份；旧revision拒绝覆盖。

## 实际验证

单元与集成测试涵盖投影链接、隐私字段、搜索章节定位、任务生命周期、选择字段应用、并发冲突、PDF身份/页序、备份校验与恢复。91项中90通过、1个可选历史样例跳过。

Chromium 检查本地完整工作台、GitHub Pages子路径静态构建，覆盖阅读/PDF/目录、图表、比较、图谱、编辑、数据库、草稿、专题。首轮综合回归发现并修复比较URL断言与PDF文本层画布定位；数据库公式测试在并行浏览器负载下超时，单独重跑全部数据库10项通过，未降低断言。UI新增AI上下文→导入→审阅→保存测试通过。

真实本地库只读检查10篇 × 320/390/768/1440px × overview/note，未见页面异常或整页溢出；四篇核心图文另行截图检查。随后压缩手机资源操作区、修复768px导航按钮，390px复查目录和正文可进入首屏。响应式模拟不等于真机触摸。

M2 / Node24 合成100、1000条元数据检索基线：1000条搜索中位数12.8–15.3ms，筛选4.4–7.1ms；10组正确性断言通过。仅为当前算法基线，不含PDF或浏览器渲染，也没有声称改造前后性能提升。

## 取舍与边界

参考实际读取的 Zotero PDF Reader、SurVis、Cytoscape.js、Distill Circuits 和 Explorable Explanations：采用选区定位、筛选上下文、局部图与条件化解释；现有规模继续使用可访问的DOM/SVG，暂不叠加多个图引擎。React Flow文档请求超时，未作为已验证API依据。

尚未验证真实模型提供方、机器人执行、真机触摸及第二浏览器内核。PDF查找限当前页文本项，不是OCR；定位返回文件页并保留引文，没有矩形批注层。草稿可按字段与章节采纳，章节任务只提议指定章节；不提供任意行级冲突合并。新三篇附录明确为局部双语摘录，不冒充完整翻译。文献列表/表格/画廊共享URL筛选、排序和选择；高级批量数据库仍保留独立保存视图。

自动测试不能判断科研结论是否成立；图表只表达原文给定协议，不构成机器人复现。公开部署与线上读回在完成后单独记录。

静态投影专项两项通过（含320px章节跳转、实验任务筛选、无本地PDF/API链接）；旧V1八项依赖已移除的历史公开多论文种子而跳过，由本地真实四篇和隔离V2用例承担多论文验收。数据库、专题矩阵与AI新增回归的最终针对性复测全部通过。线上发布记录以实际workflow结果为准。
