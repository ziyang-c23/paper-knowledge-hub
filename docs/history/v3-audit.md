# V3 迭代审计：数据库与研究实体

本轮目标是把 V2 的论文工作台扩展为可长期维护的研究资料库，补齐类似 Notion 数据库的常用视图、属性、筛选和批量操作，并让论文以外的研究对象有独立档案。代码继续保留 React/Vite/Node/JSON、loopback 本地主库和公开投影边界；没有创建远程仓库、推送或部署。

## 已实现

- `#/database`：表格、看板、画廊、列表、月历；命名视图；嵌套 AND/OR 筛选；稳定排序；列顺序、密度、归档范围、分组和日期字段。
- 类型化个人属性：文本、数字、单选、多选、日期、复选框、链接、论文关联、公式和汇总。公式使用受限表达式并保持只读；汇总从关联论文计算。属性 ID 稳定，类型变更拒绝隐式转换；0、false、空值、原型名称、未知引用和循环公式有回归测试。
- 单元格编辑、最多 1000 条原子批量修改、同 revision 撤销、看板拖动、CSV 导出、移动布局、论文侧览和完整详情入口。保存回读竞态不会把旧草稿授权为新基线。
- `#/entities`：person、institution、project、problem、concept、method、model、dataset、environment 九类档案。支持别名、简介、Markdown 档案、来源与支持范围、分类维度、手工关联、反向引用、论文聚合、归档/恢复和导出。
- 新建实体是 create-only；已有 stable ID、路由保留字 `new`、并发编辑、重新读取期间编辑和拒绝/模型关系参与汇总均有保护。公开投影明确排除实体 note、sources、relatedIds 和数据库私有属性。

## 问题驱动的两轮修复

第一轮的独立复审发现自定义文本会被错误翻译成状态、`__proto__` 会让 React 收到对象、checkbox false/true 看板显示相同、批量操作清除未保存单元格，以及视图保存后回读竞态。第二轮修正字段展示白名单、类型展示、草稿守卫、hash 导航事件、POST revision 回读一致性，并加入浏览器复现。

实体复审发现新建可用已有 ID 整体覆盖旧档案、rejected/model 关系会被汇总成确定论文联系、重新读取期间输入会被响应覆盖、`new` 会与新建路由冲突。后续增加锁内 create-only、只汇总 approved source/curator 关系、reload 交互锁和 `?create=1` 路由。

第三轮围绕长期维护的重复劳动补齐计算属性：公式使用白名单解析器，汇总沿显式论文关联计算；基础字段改变后无需手工同步派生值。保存校验拒绝未知引用、循环依赖和非数值聚合，查询、排序、分组、CSV 与 UI 统一读取当前派生结果。新增单元与 Chromium 流程分别验证公式只读、rollup 更新和结果不写回主库。

第四轮补齐普通保存的版本回查：每次成功提交前自动保存上一个主库快照到 ignored `private/history/`，最多保留 100 个；维护页可读取并下载快照，完整备份继续负责 PDF 和站点配置恢复。缺失历史明确返回 404，历史快照经过同一数据/数据库校验。

## 仍然明确未实现

未实现完整 Notion block/page 编辑器、云协作权限、时间线和图表视图、通用 CSV 映射和回收站。实体关系目前仍复用既有关系模型；关联字段表达人工资料组织，不替代来源审核。自动历史目前只保留最近 100 个主库快照，不含 PDF 原件；完整恢复仍需备份。whole-JSON 存储未做大规模性能压测，OCR、真实模型调用和公开部署仍未验证。
