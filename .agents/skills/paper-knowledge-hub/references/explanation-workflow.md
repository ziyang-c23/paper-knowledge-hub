# 从理解问题到网页解释

先写一句读者困惑，例如“为什么模型预测整个动作块，却只执行一部分？”随后明确交互前提、操作、可观察变化、来源和不能推出的结论。没有实质状态变化的高亮不算机制讲解。

## 复用真实渲染契约

查看 `src/research-visuals.jsx` 和 `schemas/dataset.schema.json`：
- `visuals.method.steps` 解释输入怎样变为输出；`modes` 切换训练/推理/微调信息。
- `visuals.method.timeline` 解释观测、预测、执行窗口，讲解时间不代表模型延迟。
- `visuals.experiments` 是实验图和表的唯一数据；保留任务、适配、指标、单位、trial count 和协议。未知用 null 或省略，不设零，不插值未报告结果。
- `explanations` 只补一个局部概念说明并引用 `sourceIds`，不复制整篇 note 或首屏摘要。
- `media` 保留原图/官方演示；`visualNarratives` 仅在现有 method/experiment 不能表达其独立目的时使用，不双写同一流程。

新增可选机制控件前检查最新 schema；不要在 Skill 中固定不存在的字段。sourceIds 必须对应当前论文来源，section 必须能打开实际笔记标题。节点来源存在不等于支持结论，仍需逐项阅读核对。

区分论文事实与教学示意。示意中的 normalized value、token 符号、轨迹和时间不冒充真实模型输出、机器人单位或运行速度。数据流、动作窗口、量化可教学演示；注意力热图、成功率曲线、机器人轨迹没有真实输出时不能伪造。

默认静止；步进能完整读懂，自动播放只是辅助。提供回退/暂停、键盘、减少动效和静态阅读替代。手机可按步骤展开，不缩成无法阅读的大图。

## 实际执行而非只写说明

1. 导出目标当前上下文，确认来源读取范围。
2. 生成候选完整记录，仅修改局部字段。关联来源已变化时重新检查解释，不自动沿用旧结论。
3. 以捕获的 revision 验证并 stage，返回网页待审 URL。
4. 用第二篇结构不同文献重复，证明契约不依赖某个 paper ID。
5. 浏览器确认候选可打开和字段差异正确；不将待审候选写成已应用。

四种专用 `ai-task` 类型继续使用服务的真实 resultTemplate：section、experiments、compare、explanation。包含来源、媒体或方法的新组合候选使用通用 ai:draft，不塞进不支持字段的专用结果。两个流程共享 revision 和人审边界，不声称已经存在一个自动执行所有阶段的调度器。
